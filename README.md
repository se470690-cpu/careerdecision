# CareerDecision

이력서·생활반경·선택 패턴으로 "지원할 회사"를 좁혀 주는 AI 취업 의사결정 웹앱 (Next.js 15 App Router, JavaScript).

## 실행

```bash
npm install
npm run dev        # http://localhost:3000
npm run build && npm start
```

Vercel 배포: GitHub에 올린 뒤 Vercel에서 Import 하면 설정 없이 배포됩니다(프레임워크 자동 감지).

## 환경변수 (모두 선택)

| 변수 | 역할 |
| --- | --- |
| `LIVE_COLLECT=1` | `/api/postings` 가 당근·캐치테이블 공식 채용 페이지에서 공고를 실시간 수집(1시간 캐시). 회사별로 읽은 공고가 너무 적으면(스냅샷이 있는 회사는 3개 미만) `lib/data.js` 스냅샷 유지. (예전 이름 `LIVE_COLLECT`도 인정) |
| `ANTHROPIC_API_KEY` | 매칭 화면의 "AI로 다시 매칭하기" 활성화 (서버에서만 사용) |
| `ANTHROPIC_MODEL` | 기본값 `claude-haiku-4-5-20251001` |
| `KAKAO_REST_API_KEY` | 카카오맵 REST API 키. 있으면 후보 탐색 화면에서 회사별 **실제 대중교통 소요시간·환승 횟수**를 조회하고, 주소 검색이 더 정확해져요 |

## 구조

- `lib/data.js` 회사 위치 12곳 + 공식 채용 페이지 공고 14개 스냅샷(2026-09-19, 출처 URL 포함)
- `lib/engine.js` 지오코딩, 통근 추정, 이력서 분석, 요건↔근거 매칭, 인터뷰 가중치, 후보 소거·점수
- `lib/daangn.js` 당근 채용 페이지 수집·파서
- `lib/resume.js` PDF/DOCX/TXT 텍스트 추출 + 스캔본·이미지는 브라우저 OCR(tesseract.js, 서버 전송 없음)
- `app/api/postings`, `app/api/match` 서버 라우트
- `app/*` 9단계 화면 (`/`, `/setup`, `/home`, `/career`, `/interview`, `/jobs`, `/match`, `/decision`, `/preference`)

## 알아둘 점

- 통근시간은 기본적으로 직선거리 기반 추정입니다. `KAKAO_REST_API_KEY` 를 설정하면 후보 탐색 화면의 “실제 대중교통 시간으로 계산하기” 버튼으로 카카오 대중교통 경로(가장 빠른 경로의 소요시간·환승·요금)를 조회합니다.
- 매칭은 개념 사전 + 문자 유사도의 규칙 기반입니다. 문맥 이해는 "AI로 다시 매칭하기"(선택)에서만 LLM이 합니다.
- 연봉은 점수에 넣지 않았습니다.
- 사용자 입력(주소·이력서·선택 기록)은 `sessionStorage`에만 저장되며 탭을 닫으면 사라집니다.

수집기는 요청 전에 사이트의 `robots.txt`를 확인하고, 허용하지 않는 경로는 읽지 않습니다(`lib/robots.js`).

회사를 추가하려면 `lib/daangn.js`처럼 목록 → 상세 → `{does, must, nice}` 로 바꾸는 수집기를 만들고 `app/api/postings/route.js`에서 합치면 됩니다.
그리팅 기반 회사(`career.○○.co.kr` 또는 `○○.career.greetinghr.com`, 페이지 하단의 “made with Greeting”)는 `app/api/postings/route.js`의 `SOURCES`에 `fetchGreeting({ base, companyId, listPath })` 한 줄과 `lib/data.js`의 회사 정보만 추가하면 됩니다. 이용약관도 확인하고 요청 간격을 두세요.

## 이력서 읽기 (PDF · 이미지)

- 텍스트가 들어 있는 PDF, DOCX, TXT는 바로 읽습니다.
- 글자가 거의 안 나오거나 깨진 PDF(스캔본, 이미지로 내보낸 PDF), 그리고 PNG/JPG는 브라우저에서 글자 인식(OCR)으로 읽습니다. 최대 5쪽.
- OCR 엔진(tesseract.js 5.1.1)은 처음 쓸 때 jsdelivr CDN에서, 한글 인식 데이터는 tessdata 서버에서 내려받습니다(첫 실행 30초 안팎). 파일 자체는 서버로 나가지 않습니다.
- OCR 결과에는 오인식이 있을 수 있어서, 읽은 뒤 텍스트 상자에서 바로 고칠 수 있게 했습니다.
- `npm run dev` / `build` 전에 `scripts/copy-assets.mjs` 가 pdf.js 워커와 한글 폰트 매핑(cmaps)을 `public/` 에 복사합니다.

## 이력서를 읽는 방식 (경험 단위)

`lib/resumeParse.js` 가 이력서를 줄 단위가 아니라 경험 단위로 이해합니다.

1. **줄바꿈 복원**: PDF 는 문단 폭에서 줄이 바뀌어 문장이 잘립니다. 폭 가까이 찬 줄이 문장 부호 없이 끝나면 다음 줄과 이어 붙입니다.
2. **구조 인식**: `회사 | 직무` 헤더, 기간, 프로젝트 제목, `Problem / Action / Result` 를 묶어 회사 → 프로젝트 → 문제·행동·성과 구조로 만듭니다.
3. **성과 수치 추출**: "검색어 비중 약 40% 감소" 같은 구절을 뽑아 근거 카드에 함께 보여 줍니다.
4. **헤더 정보**: "경력 3년 5개월", "영등포구 거주"를 읽어 경력 연차와 주소를 채웁니다.
5. **매칭**: 요건과 문장을 비교하되, 같은 프로젝트 안의 다른 문장이 채워 주는 맥락을 일부 인정하고, 근거는 자기소개보다 실제 프로젝트·경력 문장을 우선합니다.

규칙 기반이라 문맥의 깊은 뉘앙스(소프트 스킬, 은유 표현)는 점수가 후하게 나올 수 있습니다. 그 부분은 매칭 화면의 "AI로 다시 매칭하기"(선택, `ANTHROPIC_API_KEY` 필요)가 보완합니다.

## 카카오 대중교통 연동 (`lib/kakao.js`)

- `GET https://dapi.kakao.com/v2/routing/publictraffic` — 출발지·도착지 좌표 → 경로 목록(`totalTime` 초, `transfers`, `fare`). 가장 빠른 경로를 씁니다.
- 카카오 답변에 따르면 이 API는 “출발지 → 첫 승차지점”, “하차지점 → 목적지”의 도보 구간 상세 경로를 응답에 포함하지 않습니다. 총 시간에 그 도보가 포함되는지는 실제 응답으로 확인해 주세요. 필요하면 도보 경로 API(`/v2/routing/walk`)를 병행하도록 확장할 수 있어요.
- 출발지는 구·역 중심 좌표이고 회사 좌표도 일부는 근사값이라 결과는 “대략의 실제 경로 시간”입니다. 출발지를 역 이름이나 도로명으로 적으면 더 정확해집니다.
- 조회는 사용자가 버튼을 누를 때만 일어나고, 회사 수만큼(약 14곳) 호출합니다. 결과는 브라우저 세션에만 보관하고 서버에 저장하지 않습니다.
- 카카오 키는 서버 환경변수에만 둡니다(브라우저로 나가지 않음).

### 가는 길(구간별 경로)
대중교통을 조회하면 후보 카드의 “가는 길 보기”와 최종 판단 화면의 “출근 경로”에 구간별 이동 수단(버스 번호·지하철 노선, 승차→하차 정류장, 정거장 수, 구간 시간), 총 시간·환승·요금, 다른 경로 요약, 카카오맵 링크가 표시됩니다.
구간 시간의 합이 총 시간보다 작으면 그 차이를 “출발·도착 도보나 대기 약 N분”으로 표시해서, 총 시간에 도보가 포함되는지 눈으로 확인할 수 있어요. 후보 탐색 화면의 “회사별 조회 결과 보기”에서 회사별 조회 성공/실패도 볼 수 있습니다.

### 추천 이유 설계 (`explainRecommendation`)
최종 판단 화면의 “왜 이 공고를 추천했나요?”는 **계산에 실제로 쓴 값에서만** 문장을 만듭니다(LLM이 지어낸 이유가 아님).
점수 분해(항목 점수 × 내 비중) · 내 경험과 이어지는 부분(요건 ↔ 프로젝트 근거 + 성과 수치) · 걸리는 점 · 2순위와 비교 · 기준을 바꿔도 1순위인지(4가지 프리셋) · 확신도와 그 근거 · 지원서에 쓸 것.
확신도 기준(2순위와 총점 차이 8점 이상·필수 요건 70% 이상·4개 기준 중 3개 이상에서 1순위 → 높음 / 3점 미만·40% 미만·1개 이하 → 낮음)은 임의로 정한 값이라 사용자 테스트로 조정이 필요합니다.

### AI 코치 (`/api/coach`, 최종 판단 화면)
컨셉: **LLM은 결정하지 않고, 내 판단을 돕는다.** 결정은 사용자가 “내 결정 남기기”로 직접 기록합니다.

- LLM에는 계산이 끝난 **근거 목록**(`lib/coachFacts.js`: P1 점수 분해, E1~ 이력서 경험 근거, R1~ 걸리는 점, V1 2순위 비교, S1 기준 변경 결과, C1 확신도 …)만 보냅니다. 이력서 원문 전체와 주소는 보내지 않고, 화면의 “코치에게 전달되는 내용 보기”에서 전송 내용을 그대로 볼 수 있어요.
- LLM이 쓴 문장마다 근거 id(`refs`)를 요구하고, 서버가 검증합니다(`lib/coach.js validate`). 없는 id를 댔거나 근거 목록에 없는 숫자(10 이상)가 들어간 문장은 화면에 내보내지 않습니다. 단, 근거 id와 숫자가 맞아도 문장의 **의미가 미묘하게 왜곡된 경우는 이 검사로 못 막아요.**
- 공개 배포에서 API 키 요금이 새지 않도록 `COACH_ACCESS_CODE`(설정 시 화면에서 코드 입력 필요), 요청 크기 제한, IP당 1시간 20회 제한을 둡니다. 호출 제한은 서버리스 인스턴스 메모리 기준의 최선 노력이라 완벽하지 않으니, 공개 링크를 널리 퍼뜨릴 때는 Vercel의 방화벽 속도 제한을 함께 쓰세요.
- 환경변수: `ANTHROPIC_API_KEY`(필수, 없으면 코치 버튼이 “설정되지 않았다”고 안내), `ANTHROPIC_MODEL`, `COACH_ACCESS_CODE`.
